* Audio System
:PROPERTIES:
:CUSTOM_ID: audio-system
:END:
This document covers the audio types added in Phase 4: audio device, sound effects, and streaming music.

#+begin_quote
*raylib 6.0 pan behavioral change.* Sound/music/stream pan is now =[-1.0 .. 1.0]= end-to-end: =-1.0= = full left, =0.0= = centered, =1.0= = full right. graylib's public pan API was always =[-1.0 .. 1.0]=; previously it internally converted to raylib's old =[0 .. 1]= convention before forwarding. raylib 6.0 adopts the =[-1.0 .. 1.0]= convention directly, so that internal conversion has been *removed*. The public API is unchanged, but if you were relying on the (undocumented) old internal mapping, the raw value now passes straight through. Affected setters: =grl_sound_set_pan()=, =grl_music_set_pan()=, and =grl_audio_stream_set_pan()=.

#+end_quote

*** Independent voices and shared native aliases
=grl_sound_new_voice(source, error)= creates an explicitly independent native playback buffer from retained canonical PCM. Volume, pitch, pan, processors and later updates are independent; the source may be released immediately. =grl_sound_is_alias()= returns FALSE. Retained PCM is bounded to 256 MiB and missing/unsupported snapshots return a GError rather than falling back to a native alias.

=grl_sound_new_alias(source)= retains its genuine shared-memory semantics and now retains its root source automatically. Shared writes affect the root and all native aliases. The pinned SDK still leaks an opaque residual allocation on this legacy path; no private-layout cleanup or silent policy replacement is performed. Choose the independent constructor explicitly when that sharing is unnecessary.

=grl_sound_update_checked()= validates exact byte/frame cardinality before writing and keeps retained snapshots coherent. Partial writes preserve the tail; independent snapshots use copy-on-write. Stop all voices sharing native alias storage before updating it. See the [[file:../audio-ownership-contract.org][full ownership, SDK compatibility and verification contract]] for the exact WAV-context cleanup guard, resource bounds, native null-only sanitizer proof and the still-open legacy gate.

*** Stream Updating (CRITICAL!)
:PROPERTIES:
:CUSTOM_ID: stream-updating-critical
:END:
*You MUST call =grl_music_update()= in your main loop while music is playing:*

#+begin_src C
while (!grl_window_should_close (window))
{
    /* Update music stream buffers - REQUIRED! */
    grl_music_update (music);

    /* Rest of your game loop... */
    grl_window_begin_drawing (window);
    /* ... */
    grl_window_end_drawing (window);
}
#+end_src

Without calling =grl_music_update()=, music will stutter or stop, unless the music streams in the background (next section).

*** Background Streaming
:PROPERTIES:
:CUSTOM_ID: background-streaming
:END:
=grl_music_update()= decodes on the caller's thread: raylib's =UpdateMusicStream()= decodes a whole sub-buffer each time the device has consumed one, 1-3 ms of Vorbis or MP3 every few frames, all of it inside raylib's audio lock.  A background-streamed music is refilled by graylib's streaming thread instead:

#+begin_src C
grl_music_set_background_streaming (music, TRUE);   /* or the "background-streaming" property */
grl_music_play (music);
/* no grl_music_update () needed; calling it does nothing */
#+end_src

| Aspect | Behaviour |
|--------+-----------|
| The thread | one per process, started by the first background play, named =grl-music=; refills every active background music about every 5 ms (=PUMP_INTERVAL_US=) with =UpdateMusicStream()= |
| Cost when idle | none: with no background music playing (stopped, ended, never played) the thread sleeps on a condition variable |
| Control calls | =play=, =stop=, =pause=, =resume=, =seek= and =set_looping= take the thread's lock, so they never run while that music decodes; they may wait for one decode |
| Getters | =grl_music_is_playing()= and =grl_music_get_time_played()= return what the thread last published (after every refill and every control call), so they never wait on a decode; the position is at most one period (~5 ms) old |
| End of track | a non-looping music that ends is taken off the thread's list and reads as stopped within one period |
| Volume, pitch, pan, processors | unchanged: raylib's own lock covers them |
| Shutdown | =grl_audio_device_close()= (and the device's finalize) stops and joins the thread before closing raylib's device; a later background play starts it again |
| Lifetime | the thread holds no reference: disposing of a music takes it off the list under the lock |

The switch can change at any time; switching it off while the music plays hands the refills back to =grl_music_update()=.  Lock order: graylib's streaming lock, then raylib's audio lock (raylib takes it inside its functions); the device thread takes only raylib's, which is why processors and stream callbacks may not call graylib's audio functions.

Note on =looping=: raylib loads music looping; graylib now makes the loaded music follow the =looping= property, which starts =FALSE=, so a music that is never set looping now ends instead of repeating.  Call =grl_music_set_looping (music, TRUE)= for background tracks that should loop.

Tests: =tests/test-music.c= (the switch and inert calls headless; playback without =grl_music_update()=, pause, seek, end detection, stop and closing the device under a playing track with =GRL_TEST_AUDIO_DEVICE=1=).

** Complete Example
:PROPERTIES:
:CUSTOM_ID: complete-example
:END:
#+begin_src C
#include <graylib.h>

int
main (int argc, char *argv[])
{
    g_autoptr(GrlWindow) window = NULL;
    g_autoptr(GrlAudioDevice) audio = NULL;
    g_autoptr(GrlMusic) music = NULL;
    g_autoptr(GrlSound) click = NULL;
    g_autoptr(GrlColor) bg = NULL;
    g_autoptr(GError) error = NULL;

    /* Create window */
    window = grl_window_new (800, 600, "Audio Demo");
    grl_window_set_target_fps (window, 60);

    /* Initialize audio */
    audio = grl_audio_device_get_default ();
    if (!grl_audio_device_init_audio (audio))
    {
        g_printerr ("Failed to init audio\n");
        return 1;
    }

    /* Load audio files */
    music = grl_music_new_from_file ("music.ogg", &error);
    if (music == NULL)
    {
        g_print ("No music file: %s\n", error->message);
        g_clear_error (&error);
    }
    else
    {
        grl_music_set_looping (music, TRUE);
        grl_music_set_volume (music, 0.5f);
        grl_music_play (music);
    }

    click = grl_sound_new_from_file ("click.wav", &error);
    if (click == NULL)
    {
        g_print ("No sound file: %s\n", error->message);
        g_clear_error (&error);
    }

    bg = grl_color_new (30, 30, 45, 255);

    while (!grl_window_should_close (window))
    {
        /* CRITICAL: Update music stream */
        if (music != NULL)
        {
            grl_music_update (music);
        }

        /* Handle input */
        if (grl_input_is_key_pressed (GRL_KEY_SPACE))
        {
            if (music != NULL)
            {
                if (grl_music_is_playing (music))
                    grl_music_pause (music);
                else
                    grl_music_resume (music);
            }
        }

        if (grl_input_is_key_pressed (GRL_KEY_E) && click != NULL)
        {
            grl_sound_play (click);
        }

        /* Draw */
        grl_window_begin_drawing (window);
        grl_window_clear_background (window, bg);

        if (music != NULL)
        {
            gchar text[64];
            g_snprintf (text, sizeof(text), "Time: %.1f / %.1f",
                        grl_music_get_time_played (music),
                        grl_music_get_time_length (music));
            grl_draw_text (text, 20, 20, 20, NULL);
        }

        grl_draw_text ("SPACE: Play/Pause  E: Sound Effect", 20, 50, 16, NULL);
        grl_draw_fps (700, 10);

        grl_window_end_drawing (window);
    }

    return 0;
}
#+end_src

*** Callback-Based Streaming
:PROPERTIES:
:CUSTOM_ID: callback-based-streaming
:END:
Instead of pushing buffers from the game loop, a stream can let the device pull its samples from a callback on the device's own thread.  This takes synthesis off the game thread entirely and lowers latency: the device asks for small blocks just before it plays them, where a pushed stream renders a whole sub-buffer ahead.

#+begin_src C
/* runs on miniaudio's mixer thread, raylib's audio lock held */
static void
fill (gpointer buffer, guint n_frames, gpointer user_data)
{
    MySynth *synth = user_data;
    gfloat  *out = buffer;   /* the stream's format: here 32-bit float stereo */

    my_synth_render (synth, out, n_frames);
}

g_autoptr(GrlAudioStream) stream = grl_audio_stream_new (44100, 32, 2);
grl_audio_stream_set_callback (stream, fill, synth, NULL);
grl_audio_stream_play (stream);
/* ... */
grl_audio_stream_set_callback (stream, NULL, NULL, NULL);   /* detached: fill is not running and never runs again */
#+end_src

| Function | Purpose |
|----------+---------|
| =grl_audio_stream_set_callback (stream, func, user_data, destroy)= | set, replace or (with =NULL=) remove the callback; the old one is detached and its =destroy= has run when this returns |
| =grl_audio_stream_has_callback (stream)= | whether a callback fills the stream |
| =GRL_AUDIO_STREAM_MAX_CALLBACKS= (64) | streams that can have a callback at once |

- =GrlAudioStreamCallback (gpointer buffer, guint n_frames, gpointer user_data)= gets the block in the stream's own format (sample size and channels as created), at most 4096 bytes (512 frames of 32-bit stereo), several blocks back to back per device period.  It must fill every frame.
- It runs only while the stream plays (not paused or stopped).
- With a callback, =grl_audio_stream_update()= does nothing and =grl_audio_stream_is_processed()= is always =FALSE=, so an old pump loop does no work.
- The same rules as for processors: it runs with raylib's audio lock held, so it must not block, must not call graylib's or raylib's audio functions, and must not wait for a lock another thread holds while calling them.  Share state with the game through atomics or a queue (libregnum's synthesizers drain a command queue at the start of each block).
- How it is wired: raylib's =SetAudioStreamCallback()= has no user data, so graylib keeps a table of trampolines as for processors.  Setting fills a free slot before handing raylib its trampoline; removing hands raylib =NULL= first (under raylib's lock, so the callback is not running afterwards) and frees the slot.  A callback that cannot be detached because the device was closed under a loaded stream retires its slot.  When every slot is taken, setting logs a warning, calls =destroy= at once and leaves the stream without a callback.

Tests: =tests/test-audio-stream.c= (bookkeeping, slot reuse and exhaustion headless; the device pulling the callback and never calling it after removal with =GRL_TEST_AUDIO_DEVICE=1=).

** Per-Voice Processors
:PROPERTIES:
:CUSTOM_ID: per-voice-processors
:END:
A processor is a callback with user data that rewrites one voice's samples (a =GrlSound=, a sound alias, a =GrlMusic= or a =GrlAudioStream=) each time raylib mixes that voice into the device output: per-voice effects, sends into a submix bus, meters.  It wraps raylib's =AttachAudioStreamProcessor()= without modifying raylib.

| Function | Purpose |
|----------+---------|
| =grl_sound_add_processor (sound, func, user_data, destroy)= | add a processor after the existing ones; returns its id, 0 when no slot is free |
| =grl_sound_remove_processor (sound, id)= | remove one; once it returns the processor no longer runs and =destroy= ran |
| =grl_sound_clear_processors (sound)= / =grl_sound_get_n_processors (sound)= | remove all / count |
| =grl_sound_process (sound, frames, n_frames)= | run the processors over a block in place, as the device would (offline rendering, tests; not introspected) |
| =grl_music_*= / =grl_audio_stream_*= | the same five for music and audio streams |
| =grl_audio_processor_get_n_free_slots ()= | how many more processors can be attached |

*** The callback
=GrlAudioProcessFunc (gfloat *frames, guint n_frames, guint channels, gpointer user_data)= receives the voice's block in raylib's mixing format: interleaved 32-bit float, =GRL_AUDIO_PROCESSOR_CHANNELS= (2) channels at the device's rate, whatever the file's own format.  The samples are the voice's *before* raylib applies its volume and pan (raylib mixes them in after the processors), so a processor that needs the voice's level reads =grl_sound_get_volume()= / =grl_sound_get_pan()= itself; zeroing the block silences the voice in the mix.

On a playing voice the callback runs on miniaudio's thread with raylib's audio lock held: it must not block, must not call graylib's or raylib's audio functions, and must not wait for a lock that another thread holds while calling them.

*** How it is wired
raylib's processor is a bare =void (*)(void *, unsigned int)= without user data, and the block it is handed is a scratch buffer shared by all voices.  graylib therefore keeps a table of =GRL_AUDIO_PROCESSOR_MAX_SLOTS= (256) trampolines, each a distinct static function that knows its slot: adding a processor takes a free slot, stores the callback and data there, then attaches that slot's trampoline to the voice's raylib stream; removing detaches it first and clears the slot afterwards.  raylib's attach and detach take its audio lock, which the device thread holds while it runs the trampolines, so a slot is never seen half written.

- Processors run in the order they were added (raylib keeps a list per stream).
- A voice drops its processors when it is disposed, before it is unloaded (raylib does not free a stream's processors when it unloads the stream).
- An object without loaded audio keeps its processors; they run only through =*_process()=.  While the audio device is closed a processor is kept but not attached; a processor removed while the device is closed from a voice that stays loaded retires its slot for good (raylib still holds that trampoline on the buffer), so a voice surviving a device restart never calls another voice's processor.
- When every slot is taken, =*_add_processor()= logs a warning, calls =destroy= on the data at once and returns 0.

#+begin_src C
/* halve one voice's level before it is mixed */
static void
halve (gfloat *frames, guint n_frames, guint channels, gpointer user_data)
{
    guint i;

    for (i = 0; i < n_frames * channels; i++)
        frames[i] *= 0.5f;
}

guint id = grl_sound_add_processor (alias, halve, NULL, NULL);
/* ... */
grl_sound_remove_processor (alias, id);

** Sound vs Music: When to Use Each
:PROPERTIES:
:CUSTOM_ID: sound-vs-music-when-to-use-each
:END:
| Feature         | GrlSound      | GrlMusic           |
|-----------------+---------------+--------------------|
| Memory          | Fully loaded  | Streamed from disk |
| Latency         | Instant       | Slight delay       |
| Best for        | Short effects | Long tracks        |
| Overlapping     | Supported     | Single instance    |
| Requires update | No            | Yes (every frame)  |

*Use GrlSound for:*

- Button clicks
- Explosions
- Footsteps
- UI feedback
- Any sound < 5 seconds

*Use GrlMusic for:*

- Background music
- Ambient sounds
- Voice overs
- Any audio > 10 seconds
