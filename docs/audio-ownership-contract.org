#+title: Owned audio cleanup and independent voice contract

The standalone SDK warning scope below is not the configured game's release gate. The subsequent [[file:../../completion/docs/sdk-build-warning-proof.org][configured root warning proof]] records the game-owned padded-copy adapter and a warning-free fresh default parent/dependency build at -O2. The unrelated vanilla SDK baseline remains distinct from that passing port configuration.

* Disposition
The fingerprinted bundled SDK's WAV-context leak is repaired through its public Music descriptor and MemFree API. An explicit independent-voice constructor avoids the native alias allocation leak without changing the shared-memory meaning of =grl_sound_new_alias()=. The independent-policy null-backend sanitizer gate passes; the legacy shared-alias gate remains open. No opaque AudioBuffer layout, borrowed field free, vendor source patch or sanitizer suppression is used.

* WAV decoder ownership and compatibility guard
The wrapper owns the native Music returned by its file/memory constructors. When the constructor is known to load WAV, it captures the original public =Music.ctxData= pointer only if all of the following match: static bundled SDK mode; SDK revision =dbc56a87da87d973a9c5baa4e7438a9d20121d28=; a clean tracked SDK tree; =raudio.c= SHA-256 =2a5b42a701fd872dbf6a9715964344ce44b891bdcd7643122774d5cac9589812=; =raylib.h= SHA-256 =047e7255f93f8c34039cab906ad76136706b5c7b4c5b5b065d84141963ee9b6b=; and public version 6.0. On that source, UnloadMusicStream uninitializes the WAV decoder but does not free the separately allocated decoder object. The wrapper calls native unload first, then MemFree on its saved original pointer, then releases its encoded memory buffer. This includes zero-frame/failed-native-stream constructor unwind. The existing background-pump unregister/join and processor detachment ordering is preserved.

The capability is computed from explicit build inputs, not runtime environment inspection. A content-stable generated header under each build directory invalidates stale music objects when SDK selection changes, including a new SDK with older source timestamps. Command-line attempts to force the private capability do not override the computed source checks. A changed, dirty, unrecognized or system SDK has capability zero: no added free is performed, so a future SDK that frees the context itself is not double-freed. Such SDKs retain their native ownership behavior and are not covered by this pinned-source zero-leak claim; an update needs an ownership review before enabling another compatibility case.

The linked native archive must be built from the selected SDK source. Replacing it independently with a different implementation is outside this compile-time capability contract. The engine's explicit Wayland-only archive uses the same committed SDK source, so the same WAV ownership case applies. Raw SDK descriptor mutation/library hot-swapping while wrapper objects exist is unsupported; the saved constructor pointer is not replaced by a caller's borrowed view.

Music construction now reports =G_IO_ERROR_NOT_INITIALIZED= before native loading when no device is current, never opening one implicitly. Encoded memory counts must fit the SDK's signed byte-count range before copying. File-not-found and malformed/empty input still fail explicitly. File and memory WAV streams both participate in the native lifetime stress test.

* Native shared aliases and independent voices
** Legacy shared-memory contract
=grl_sound_new_alias(source)= still calls the public native alias API and shares sample memory. Its volume/pitch/pan and processor state are separate native voice state. It now strongly retains the original root source, flattening alias-of-alias ownership rather than creating parent/child reference cycles. Callers can release their source reference while aliases live. Alias native unload happens before the final root reference is released.

The pinned SDK's UnloadSoundAlias omits an opaque converter residual allocation. The wrapper cannot legitimately free that allocation through public APIs, so the legacy shared-alias cleanup limitation is retained and documented. No independent copy is covertly substituted under this symbol, and no zero-leak claim includes this path.

** Explicit independent policy
=grl_sound_new_voice(source, error)= allocates an ordinary owned native Sound buffer from the source's retained immutable canonical PCM. =grl_sound_is_alias()= returns FALSE. It never uses LoadSoundAlias. The native buffer has independent playback state, gain/pitch/pan, processors and updates. The source object can be finalized immediately: the new voice owns its native playback storage and retains its immutable PCM snapshot independently. Matching-format voices share a GBytes snapshot reference, not native playback storage; writes publish a new snapshot rather than mutating a shared GBytes.

All existing sound creation routes converge on the same ownership adapter: file -> owned GrlWave -> public Wave conversion; encoded memory -> owned GrlWave; borrowed raw PCM -> synchronous native copy; and caller-owned GrlWave -> synchronous native copy. Resource construction continues to delegate to the encoded-memory route. Every retained-copy arithmetic operation is checked before copying. Retention is limited to =GRL_SOUND_VOICE_MAX_PCM_BYTES= (256 MiB), covering both original and canonical playback bytes. Larger legacy sounds remain usable but have no retained snapshot; new_voice then returns =G_IO_ERROR_NOT_SUPPORTED=. The limit does not silently reject or truncate a legacy native alias. It is not a global memory/voice-count budget.

Raw PCM metadata must describe complete frames, positive rates/channels and 8/16/32-bit samples. Invalid division/counts fail before copying or native allocation. Encoded sound counts must fit the SDK's signed byte count. An independent voice requires an explicitly initialized audio device and returns a meaningful GError on unsupported snapshot, absent device or native construction failure. It never initializes hardware.

** Checked writes and callback lifetime
=grl_sound_update_checked(self, data, data_size, frame_count, error)= validates exact playback-format byte/frame cardinality and allocated frame capacity before any write. Partial writes preserve the untouched tail. Writes through either a native shared alias or its root also update the root's retained snapshot, so a subsequently created independent voice sees the current data. Existing independent voices retain their own prior snapshots and native buffers. The old void update method uses the checked path after its programming-contract guards.

Callers must stop every voice sharing native alias storage before updating it: the native SDK does not synchronize a shared write against other aliases' playback. No new cross-thread Sound-control guarantee is introduced. Stream callbacks and processors retain their existing no-block/no-audio-reentry rules. Sound disposal stops its voice before detaching its processors; detachment synchronizes with the device callback, and native storage is unloaded only afterward. Release sounds/streams before closing their device. The existing background-music close/reopen behavior and pump locking are preserved.

* Acceptance evidence
- =tests/test-audio-owned.c= supplies executable-owned public SDK adapters; its FakeBuffer is explicitly a test type, not an SDK layout. Five GTests cover exactly-one context deallocation for the known old SDK, a simulated fixed SDK and non-WAV ownership; independent/native-alias distinction; source retention and absence of cycles; immutable snapshot copy-on-write; shared partial writes; malformed cardinalities; absent device/snapshot; and 100 iterations through each of four sound constructor routes. The same five checks pass under ASan/UBSan with unsuppressed LSan.
- Full-typelib tests verify that both policies remain public, the independent constructor returns full nullable ownership with GError, and checked writes expose the actual byte-array length. Eight metadata checks pass against the complete namespace.
- The explicit kernel-restricted null-only fixture, retained in the sibling engine's ignored build directory, executes 30 WAV-music/independent-voice/callback-stream lifetimes across three device open/close cycles. Half of the music objects are file-backed and half memory-backed. It replaces pull callbacks, detaches music processors, disposes playing voices with processors, drops sources before playback, checks weak-reference finalization, and validates callback/destroy ordering. Three empty-WAV construction failures are unwound too. It also executes 100 file + 100 encoded-memory + 100 raw-PCM + 100 GrlWave source/independent-voice smoke cases. The instrumented wrapper/helper/fixture exit 0 with leak detection enabled and no ASan/UBSan/LSan report. The SDK archive itself is not instrumented; its allocations are still observed by ASan's allocator interceptors. This is finite stress evidence, not a TSAN proof or hardware/audible acceptance.
- A separately compiled legacy-policy variant still fails LSan with 1,920 bytes in 30 allocations (one native alias residual per lifetime), instead of the original 14,160 bytes/60 allocations. Its successful lifetime assertions are not relabeled as overall acceptance. Existing parent callers using new_alias retain that open gate until they explicitly choose independent voices or the SDK fixes its native alias unload.
- A fresh normal SDK rebuild still emits four unchanged upstream GCC warnings in =external/m3d.h= and =rcore.c=. No vendor edit or reduced warning flag is used. Prepared-archive wrapper/all/GIR builds are warning-free; the fresh default SDK zero-warning gate is not declared passed.

The dedicated null helper asserts filesystem/socket barriers before device startup and forces exactly miniaudio's null backend. No ordinary test enables an audio device; regular tests pass =--no-sound= through the silent wrapper. No credential inspection or inherited-environment dump is used. Source changes remain unstaged in the ongoing merge; no version/SO, gitlink, commit, tag or push is part of this work.
